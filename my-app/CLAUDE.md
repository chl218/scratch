## Commands

- `npm run dev` — dev server at http://localhost:3000 (Turbopack)
- `npm run build` — production build; also the main type-check gate (there is no separate `tsc` script)
- `npm run lint` — ESLint 9 flat config (`eslint-config-next` core-web-vitals + typescript)
- `npx eslint app/page.tsx` — lint a single file

No test framework is set up yet.

## Stack and architecture

Freshly bootstrapped `create-next-app` project: Next.js 16.4 (App Router only, under `app/`), React 19.3, TypeScript strict, Tailwind CSS v4.

Things that differ from older Next.js/Tailwind setups:

- **Next.js docs are bundled locally** in `node_modules/next/dist/docs/` (`01-app`, `03-architecture`, …). Per AGENTS.md, check them before using any Next.js API instead of relying on memory.
- **`next.config.ts` enables `cacheComponents`, `partialPrefetching`, and `experimental.agentFeedback`.** `cacheComponents` changes data fetching and caching defaults (dynamic by default, opt in with `"use cache"`), so read the caching docs before writing data-fetching code.
- **Tailwind v4 runs through a Turbopack loader rule** (`@tailwindcss/turbopack` on `*.css` in `next.config.ts`), not PostCSS. There is no `tailwind.config.*`; theme tokens live in `app/globals.css` via `@import "tailwindcss"` and `@theme inline`, with light/dark CSS variables (`--background`, `--foreground`) and Geist fonts wired up as `--font-sans` / `--font-mono`.
- **Route prop types are global helpers** generated by Next (e.g. `LayoutProps<"/">` in `app/layout.tsx`); types come from `.next/types` / `.next/dev/types`, so run `dev` or `build` once if they're missing.
- Path alias `@/*` maps to the project root.
- `next dev` rewrites the managed block in `AGENTS.md`; commit that change rather than reverting it.
